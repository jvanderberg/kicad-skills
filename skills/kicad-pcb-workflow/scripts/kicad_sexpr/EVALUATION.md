# Evaluation: existing Python libraries for KiCad 10 files (2026-10-24)

Question: is there a library the skills can build on to read, modify and generate KiCad 10 schematics and boards
headless, instead of hand-formatted s-expression text? Candidates: **kiutils**, **kicad-skip**, **KiCadFiles**
(found on PyPI while looking), and KiCad's official IPC API bindings **kicad-python (kipy)**.
Decision: **none fits; `kicad_sexpr` was written instead** (small, MIT, no dependencies). Details below.

## Method

Every library parsed each file and wrote it back unchanged. The result was dropped into a copy of its project and
compared with the untouched copy, with KiCad 10.0.1 as the judge (`eval/eval_libraries.py`, run on macOS, system
`python3` 3.9.6 in a venv):

- **tokens**: same token stream as the original (whitespace ignored); "bytes" = identical file;
- **lost**: s-expression keywords that occur fewer times after the round trip;
- **DRC / ERC / netlist**: `kicad-cli pcb drc --schematic-parity`, `sch erc`, `sch export netlist` compared with the
  original's results; **SVG**: `fp/sym export svg` compared;
- **re-save**: `kicad-cli pcb|sch|fp|sym upgrade --force` on both copies; identical output means KiCad loaded
  identical content (library files get random uuids on every load, so uuids are masked there).

Files (all saved by KiCad 10.0.x unless noted): five boards (minipc-power, pixel_blit, pico-stretch2,
ThreeRailCharger, rp2350b_dev; between them teardrops, embedded fonts, keepout rule areas, net ties, images,
stackups, 4-layer tenting); four schematic sheets (minipc-power, generated by its own writer; pixel_blit Power, with
pasted library symbols; pico-stretch2; ThreeRailCharger Charger, a hierarchical sub-sheet); four footprints (KiCad
library QFN-24 and SOT-23-6 style generator output, a USB-C connector, ESP32-S3 module with a keepout zone, a
JLCImport footprint); three symbol libraries (KiCad power and MCU_RaspberryPi, the minipc-power library).
KiCad's demo projects are not in this install (`SharedSupport/demos` does not exist), and none of the local KiCad 10
files contains embedded files or tuning patterns, so those tokens were not exercised.

Cause of the board failures, from the tracebacks: KiCad 10 writes pad and track nets by name only,
`(net "VSYS")`; kiutils (`Net.from_sexpr` reads `exp[2]`) and KiCadFiles (casts the first value to an int) expect
KiCad <= 9's `(net 12 "VSYS")`. kicad-skip fails in its own coordinate handling while loading.

`kicad_sexpr` was also run over KiCad's installed libraries: 1765 files (all symbol libraries, every tenth
footprint), 1487 byte-identical, 278 token-identical (files written by the footprint generator or other tools, not
by KiCad), 0 failures. Its test suite repeats the KiCad-judged checks on files it generates.

## The candidates

| | kiutils | kicad-skip | KiCadFiles | kicad-python (kipy) |
|---|---|---|---|---|
| KiCad 10 boards | parse fails | parse fails | parse fails | n/a (talks to a running KiCad) |
| lossless round trip | no (drops KiCad 8-10 tokens) | schematics only (token-level, not KiCad's layout) | no | n/a |
| build from scratch | typed dataclasses; `create_new()` writes version `20211014` | `collection.new()` adds an element from a built-in template (`ElementTemplate`), then you set its attributes | typed dataclasses | through the running editor |
| file types | sch, pcb, sym, mod, wks, lib tables | sch, pcb | sch, pcb, sym, mod, pro, dru, lib tables | PCB editor objects |
| maintenance | PyPI 1.4.8 2024-02-02; last commit 2024-05-02; 19 open issues | PyPI 0.2.5 2024-02-16 (only release); last commit 2024-02-16; 28 open issues | PyPI 1.0.5 2025-10-06 (first 1.0.0 2025-09-24) | PyPI 0.8.0 2026-08-30, KiCad project |
| license | GPL-3.0 | LGPL-2.1+ | MIT | MIT |
| install | pip, no deps | pip + sexpdata | pip, no deps | pip + protobuf, pynng, jsonschema; KiCad running |

- **kiutils**: GPL-3.0 is a poor fit for an MIT repo that would vendor or require it, and it is behind the format
  (no KiCad 10 boards; silently drops `hide`, `do_not_autoplace`, `exclude_from_sim`, `embedded_fonts`, ... in
  schematics and libraries, which changed one netlist and every symbol render).
- **kicad-skip**: the closest in spirit (a generic tree over sexpdata, so schematics survive token for token), but it
  cannot load KiCad 10 boards, has no library-file support, no typed builders (new elements come from fixed
  templates), one release in early 2024, LGPL.
- **KiCadFiles**: MIT and recent, but its fixed per-token classes are what breaks: on these files it drops tokens and
  writes footprints and schematics KiCad then refuses to load.
- **kicad-python / IPC API**: the official way forward for interactive scripting (its description notes the SWIG
  `pcbnew` bindings are removed in KiCad 11), but in its own words it "requires that KiCad be running with the API
  server enabled" and "It is not possible to use kicad-python to manipulate KiCad design files without KiCad
  running". kicad-cli 10.0.1 has no API-server command (its subcommands are fp, jobset, pcb, sch, sym, version). The
  skills generate and check files headless, often while the user's KiCad is closed, so this cannot be the file layer.

## Decision

Write a small layer in the repo instead (`kicad_sexpr`, about 2200 lines including the builders): a generic lossless
tree whose writer reproduces KiCad's layout byte for byte, plus typed builders for the items generators need. It
needs only python3 (3.9 works), matches the repo's MIT license and the skills' install burden (python3 + KiCad), and
every KiCad 10 token survives because nothing is modelled as a fixed class.

Reproduce: `python3 -m venv venv && venv/bin/pip install kiutils kicad-skip kicadfiles`, then
`venv/bin/python eval/eval_libraries.py cases.json OUT_DIR` (cases format in the script's docstring).
